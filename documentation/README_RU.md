🎯 Цель проекта
•	Приложение решает задачу изучения химических формул в интерактивной и увлекательной форме.
•	Эта задача важна, так как традиционное обучение химии может быть абстрактным; визуализация и «сборка» молекул помогают лучше запоминать материал.
•	Целевая аудитория: Студенты, любители химии и преподаватели.
________________________________________
📌 Требования к приложению
Функциональные требования
•	Сборка химических формул из отдельных элементов.
•	3D-визуализация молекулярных моделей через интеграцию с MolView.
•	База данных веществ, классифицированных по сложности и типу.
•	Режим «Свободная лаборатория» для экспериментов.
Нефункциональные требования
•	Производительность: Плавный 3D-рендеринг и быстрые запросы к базе данных.
•	Удобство использования: Интуитивно понятный интерфейс с четкой «Палитрой элементов».
•	Надёжность: Правильная обработка нормализации химических формул и состояний ошибок.
________________________________________
🧠 Общая архитектура
•	Выбранный подход:
–	Архитектура на основе Activity (стиль MVC)

•	Почему выбран именно он:
Просто и эффективно для игрового приложения с отдельными экранами и прямым взаимодействием с оборудованием/интерфейсом.

•	Основные компоненты системы:
- Activity: Управление состояниями интерфейса и взаимодействием с пользователем.
- База данных SQLite: Постоянное хранение химических данных и прогресса.
- WebView: Для качественного 3D-рендеринга молекул.
- Утилиты: Специализированная логика для парсинга и нормализации формул.

Анализ пакетов:
- `zeev.fraiman.assemblethemolecule`: Основные Activity.
- `database`: Управление SQL.
- `model`: POJO классы для элементов и веществ.
- `adapter`: Логика RecyclerView.
- `utils`: Вспомогательные классы бизнес-логики.
Эта структура помогает масштабированию за счет отделения работы с данными от логики интерфейса.

🧩 Подробное описание классов
📌 Класс: MainActivity
Роль: Точка входа и навигационный узел.
Ответственность: Перенаправление пользователя в различные игровые режимы или настройки.
Основные методы:
- `onCreate()` — Инициализирует кнопки и слушатели кликов.
- `btnPlay.setOnClickListener()` — Запускает игровой режим.

📌 Класс: GameActivity
Роль: Основной игровой движок.
Ответственность: Управление процессом сборки формулы и валидацией.
Основные методы:
- `onElementClick()` — Добавляет элемент в формулу.
- `checkFormula()` — Проверяет сборку по базе данных.

📌 Класс: HelperDB
Роль: Слой данных (Data Layer).
Ответственность: Заполнение данных из JSON-активов и управление операциями SQLite.

🔄 Диаграмма работы приложения
Сценарий: Пользователь хочет увидеть 3D-модель.
1. Пользователь открывает «Вещества» (Substances).
2. Нажимает на «Модель молекулы» для конкретного вещества.
3. Название/формула вещества передаются через Intent в `MoleculeModelActivity`.
4. Activity запрашивает MolView через WebView для рендеринга интерактивной 3D-модели.

🎨 UI/UX анализ
•	Интерфейс разработан с использованием крупных кнопок и сеточного макета для удобства использования на мобильных устройствах.
•	Какие принципы использованы:
–	Простота: Понятная «палитра» элементов.
–	Логичность: Рабочий процесс сверху вниз (Задача -> Рабочая область -> Управление).
–	Доступность: Четкие шрифты и высококонтрастные кнопки элементов.
•	Что можно улучшить: Поддержка темной темы и тактильная отдача (вибрация).
________________________________________
⚙️ Работа с потоками
•	Используются:
- Handler / Looper: Для синхронизированных обновлений интерфейса (экраны загрузки).
- Внутренняя многопоточность WebView: Для рендеринга 3D.
•	Почему выбран этот способ: Для сохранения отзывчивости интерфейса во время тяжелого рендеринга или загрузки данных.
•	Как предотвращаются:
–	Зависания (ANR): Длительные операции с базой данных минимальны; WebView обрабатывает сложный рендеринг асинхронно.
–	Утечки памяти: Тщательное управление контекстом в адаптерах и статических картах.
________________________________________
💾 Работа с данными
•	Данные хранятся в базе данных SQLite, инициализируемой из JSON-файлов.
•	Почему выбран этот способ: Обеспечивает быстрый поиск, сортировку и возможность отслеживания прогресса в офлайн-режиме.
•	Как обеспечивается:
–	Сохранность: Реляционная структура для элементов и веществ.
–	Корректность: Нормализация формул перед сравнением.
________________________________________
🌐 Работа с сетью
•	Запросы выполняются через WebView к MolView.org.
•	Обработка ошибок: Плейсхолдеры загрузки и обработка таймаутов.
•	Что происходит при отсутствии интернета: Базовый игровой процесс работает офлайн; для 3D-моделей требуется интернет.
________________________________________
🔐 Безопасность (базовый уровень)
•	Чувствительные пользовательские данные (пароли/ФИО) в настоящее время не собираются.
•	Защита данных: Стандартная песочница приложений Android.

🧪 Тестирование
•	Какие тесты есть:
–	Unit-тесты: Проверка логики нормализации формул в `FormulaUtils`.
